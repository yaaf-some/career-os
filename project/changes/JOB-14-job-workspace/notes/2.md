# Unit 2: job overview and fit (doc notes)

## API (for `docs/architecture.md`)

| Route | Purpose |
|---|---|
| `PATCH /api/jobs/{id}` | Edit title, company, URL, location, workplace type, salary, years label. Only sent fields change; `null` clears an optional one. |
| `PUT /api/jobs/{id}/archive` | `{archived}`; archiving twice keeps the first date. |
| `DELETE /api/jobs/{id}?confirm=true` | Permanent. |
| `GET /api/jobs/{id}/annotations` | Notes and tags. |
| `POST /api/jobs/{id}/notes`, `PATCH`/`DELETE .../notes/{note_id}` | Notes (10,000 characters at most). |
| `POST`/`PATCH`/`DELETE /api/jobs/{id}/tags` | Add, rename, remove (40 characters, 30 per job, duplicates ignore case). |
| `POST /api/ai/score/{job_id}` | Redo fast scoring for one job. |

## Behavior worth documenting

- **Edits survive scans.** Ingest does nothing on a known `canonical_key` except fill a missing or cut-off description.
- **`canonical_key` on URL change** (glossary): it is the identity a scan uses. A scanned job keeps its key, so the old posting is not re-added; a manual job's key follows the new URL. A URL another job uses is refused with 409.
- **Delete** cascades to evaluations, the application (and email draft), notes, tags, contact links, activities, events, tailor runs and Drive link rows. Gmail thread and calendar rows are unlinked. Nothing in Google is deleted. A later scan can re-add the posting; archive keeps it hidden.
- **Rescore one** may move a job still waiting for review to skipped, like batch scoring. Saved, skipped and applied jobs keep their status. If the description changes while the model is working, the result is dropped (409).

## Trust (for `docs/trust.md`)

Evaluation reports are model output derived from untrusted postings. The web renders them as React text only: no raw HTML, no clickable links, no images.

## Known gaps outside this unit

- `fill_missing_description` (`state.rs`) treats any 3,900–4,000 character description as cut off, so a pasted one of that length can be replaced by a longer scanned one.
- `score_pending_batch` (`state.rs`) can save a score made from a description that changed during the model call.
- Nothing writes `jobs.guard_flags_json` yet, so the Fit tab's guard card stays hidden until ingest stores the scanner's flags.
- Tracker and follow-up queries do not filter `archived_at` (only the job list, scoring, rescoring and Today's top matches do).
